# S0 — i18n-02: Limpiar hardcodes español en /publish, WalletSetup y onboarding

**Sprint:** 5
**Tipo:** Tech Debt / i18n
**Prioridad:** Alta
**Estimación inicial:** M (3–5 puntos)
**Fecha S0:** 2026-02-26

---

## Historia de Usuario

> **Como** usuario del marketplace WasiAI,
> **quiero** que la interfaz de publicación de agentes, el setup de wallet y el onboarding
> se muestren en el idioma correcto según mi preferencia de locale,
> **para que** no vea strings mezclados en español cuando el locale activo es inglés (`/en/`).

---

## Contexto y motivación

Durante la implementación inicial de i18n (i18n-01), se migró el NavBar y páginas principales.
Sin embargo, los componentes de publicación (`/publish`), `WalletSetup` y `OnboardingStep1`
conservan strings hardcodeados en español. Esto rompe la experiencia para usuarios en locale `en`.

El sistema i18n ya está configurado:
- `next-intl` activo
- `defaultLocale = 'en'`
- Archivos `messages/en.json` y `messages/es.json` existentes

Esta HU cierra ese deuda técnica con scope quirúrgico y verificable.

## Riesgos

| Riesgo | Probabilidad | Impacto | Mitigación |
|--------|-------------|---------|-----------|
| `useTranslations` no disponible en Client Components sin wrapper | Media | Alto | Verificar si Step1Basic/Step2Product son Client Components; si es así, usar `useTranslations` de `next-intl/client` o asegurarse que el provider esté en el layout |
| Colisión de keys con namespace existente | Baja | Medio | Revisar `messages/en.json` antes de agregar claves |
| `"Guardando…"` compartido entre componentes — riesgo de divergencia de copy | Baja | Bajo | Centralizar en `common.saving` si aplica |
| PublishForm.tsx es Server Component y no puede usar `useTranslations` directo | Media | Alto | Verificar si es SC o CC; si es SC usar `getTranslations()` |
| Strings en `"optional · máx 5MB"` con caracteres especiales (·) | Baja | Bajo | Copiar exacto al JSON con encoding correcto |
