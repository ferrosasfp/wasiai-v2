## 1. Descripción

Los consumers de WasiAI cargan USDC en su API key activa para invocar agentes. Actualmente no existe ningún indicador visual del saldo disponible: el usuario sólo descubre que se quedó sin fondos cuando recibe un error `402 Payment Required`. Esto genera fricción innecesaria, abandono de flujos y desconfianza en la plataforma.

Esta HU agrega un indicador persistente en la navbar que muestra el saldo disponible (`budget_usdc - spent_usdc`) de la API key activa del usuario autenticado, con actualizaciones periódicas y estados visuales claros (suficiente / bajo / agotado).

---

## 2. User Stories

### US-1 — Ver saldo disponible
**Como** consumer autenticado,
**quiero** ver mi saldo de USDC disponible en la navbar mientras navego por WasiAI,
**para** saber si puedo invocar agentes sin interrupciones.

### US-2 — Saldo bajo como señal de advertencia
**Como** consumer autenticado,
**quiero** recibir una señal visual cuando mi saldo esté por agotarse (< 20% del budget),
**para** poder recargar antes de quedarme sin fondos.

### US-3 — Sin API key activa
**Como** consumer autenticado sin API key configurada,
**quiero** ver un indicador claro en la navbar que me invite a crear una,
**para** saber cómo empezar a usar los agentes.

### US-4 — Actualización automática del saldo
**Como** consumer autenticado,
**quiero** que el saldo se actualice automáticamente después de invocar un agente,
**para** no necesitar refrescar la página para ver el estado real.

## 3. Criterios de Aceptación

### AC-01 — Renderizado del indicador
- [ ] El indicador aparece en la navbar principal para cualquier usuario autenticado
- [ ] El indicador NO aparece para usuarios no autenticados (guests)
- [ ] Se ubica en el lado derecho de la navbar, antes del avatar/wallet

### AC-02 — Cálculo y display del saldo
- [ ] Muestra `budget_usdc - spent_usdc` como saldo disponible
- [ ] Formato: `$X.XX USDC` (2 decimales, símbolo dólar)
- [ ] Dato obtenido de `GET /api/v1/agent-keys/me`
- [ ] Si `is_active = false` para la key activa, muestra estado "Key inactiva"

### AC-03 — Estados visuales
- [ ] **Verde / normal:** saldo ≥ 20% del `budget_usdc`
- [ ] **Amarillo / warning:** saldo entre 1% y 19% del `budget_usdc` — tooltip "Saldo bajo, recarga pronto"
- [ ] **Rojo / agotado:** saldo = 0 o negativo — tooltip "Saldo agotado — no puedes invocar agentes"
- [ ] **Gris / sin key:** usuario sin API key activa — muestra "Crear API key" (link a /dashboard/keys)

### AC-04 — Actualización automática
- [ ] El saldo se refresca cada 60 segundos mediante polling al endpoint
- [ ] También se refresca inmediatamente después de una invocación exitosa a un agente (evento local)
- [ ] Durante el fetch, muestra skeleton loader (no spinner bloqueante)

### AC-05 — Performance y resiliencia
- [ ] El fetch del saldo no bloquea el render inicial de la navbar
- [ ] Si el endpoint falla (5xx / timeout), el indicador muestra el último valor conocido con un ícono de advertencia sutil
- [ ] El polling se pausa cuando la ventana pierde el foco (`visibilitychange`) y se reanuda al recuperarlo

### AC-06 — No autenticado / carga
- [ ] El componente no monta ni ejecuta fetch si no hay sesión activa
- [ ] Si la sesión expira, el indicador desaparece sin errores en consola

### AC-07 — Accesibilidad
- [ ] El indicador tiene `aria-label="Saldo disponible: $X.XX USDC"`
- [ ] Los estados de color incluyen un ícono o texto complementario (no solo color)

## 4. Scope

### Incluido en UX-05
- Componente React `<ApiKeyBalance />` en la navbar
- Hook `useApiKeyBalance()` con polling y pausa por visibilidad
- Integración con endpoint existente `GET /api/v1/agent-keys/me`
- 3 estados visuales (normal / warning / agotado) + estado sin key
- Skeleton loader durante fetch inicial

### Excluido de UX-05 (futuras HUs)
- Notificaciones push / email cuando el saldo cae bajo ← UX-06
- Recarga de saldo desde la navbar (botón top-up inline) ← UX-07
- Soporte multi-key (selector de key activa) ← UX-08
- Historial de consumo por agente ← UX-09
- Modificación del endpoint `GET /api/v1/agent-keys/me` (ya existe y devuelve los campos necesarios)

## 5. Riesgos

| # | Riesgo | Probabilidad | Impacto | Mitigación |
|---|--------|-------------|---------|------------|
| R1 | El endpoint no devuelve `budget_usdc` / `spent_usdc` en la respuesta actual | Media | Alto | Verificar shape de respuesta antes de S1; ajustar endpoint si falta |
| R2 | Polling cada 60s genera carga en DB si hay muchos usuarios simultáneos | Baja | Medio | Evaluar caché corto (30s) en edge con `stale-while-revalidate`; Upstash si escala |
| R3 | El usuario tiene múltiples API keys — ¿cuál mostrar? | Media | Medio | Mostrar solo la marcada como `is_active = true`; si hay >1 activa, mostrar la primera y documentar deuda técnica |
| R4 | Flash de "sin key" antes de que llegue la respuesta del fetch | Alta | Bajo | Mostrar skeleton en vez de estado vacío durante los primeros 2s |
| R5 | Saldo puede ser negativo si hay concurrencia de invocaciones | Baja | Bajo | Mostrar `$0.00` si el valor calculado es negativo; tratar como agotado |

---

## 6. Dependencias

- **Endpoint:** `GET /api/v1/agent-keys/me` — debe devolver `budget_usdc`, `spent_usdc`, `is_active`
- **Auth:** sesión Supabase activa (`useSession`)
- **UI:** Tailwind + componentes existentes de la navbar
- **No requiere:** migración de DB, cambios de contrato, nuevas tablas
