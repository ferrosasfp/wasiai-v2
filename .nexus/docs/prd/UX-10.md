# S0 — UX-10: Language switcher EN/ES en WasiNavBar

**Sprint:** 5
**Tipo:** Feature / UX
**Prioridad:** Alta
**Estimación inicial:** S (1–2 puntos)
**Fecha S0:** 2026-02-26

---

## Historia de Usuario

> **Como** usuario de WasiAI,
> **quiero** poder cambiar el idioma entre inglés y español desde la barra de navegación,
> **para que** pueda usar la plataforma en mi idioma preferido sin tener que modificar manualmente la URL.

---

## Contexto y motivación

El sistema i18n (next-intl) ya está operativo con rutas `/en/` y `/es/`. Sin embargo, no existe ningún control de UI que permita al usuario cambiar el locale. El cambio de idioma requiere editar la URL manualmente, lo que es completamente inaceptable en producción.

Esta HU agrega el toggle de idioma EN | ES directamente en `WasiNavBar`, visible en desktop y mobile, con cambio de URL inmediato y sin pérdida de la ruta actual.

---

## Acceptance Criteria

### AC-1 — Toggle visible en NavBar
- [ ] El NavBar muestra un control de idioma con las opciones `EN` y `ES`.
- [ ] El locale activo está visualmente diferenciado (bold, subrayado o color distinto).
- [ ] El control es visible en viewport desktop (≥ 768px).
- [ ] El control es visible en viewport mobile (< 768px) — ya sea en el menú hamburguesa o en la barra principal.

### AC-2 — Cambio de locale via URL
- [ ] Al hacer clic en `EN`, la URL cambia de `/es/[ruta]` → `/en/[ruta]` sin perder la ruta actual.
- [ ] Al hacer clic en `ES`, la URL cambia de `/en/[ruta]` → `/es/[ruta]` sin perder la ruta actual.
- [ ] El cambio usa `useRouter` de `next-intl` o el helper de locale switching correspondiente — **no** un `window.location.href` manual.
- [ ] No se pierde el pathname al cambiar locale (e.g., `/en/publish` → `/es/publish`, no `/es/`).

### AC-3 — Persistencia
- [ ] Después del cambio de locale, navegar a otra página del sitio mantiene el locale seleccionado.
- [ ] El locale persiste en la cookie/header manejado por el middleware de next-intl (no requiere implementación adicional si el middleware ya lo hace).

### AC-4 — Accesibilidad básica
- [ ] El control tiene `aria-label` descriptivo (e.g., `"Change language"` / `"Cambiar idioma"`).
- [ ] Es clickeable con teclado (no solo con mouse).

### AC-5 — Sin regresión en NavBar
- [ ] El resto del NavBar (logo, links, wallet connect button) funciona igual que antes.
- [ ] No hay layout shift visible al agregar el switcher.
- [ ] En mobile, el switcher no rompe el layout del menú existente.

## Implementación de referencia (guía para S1)

```tsx
// Patrón recomendado con next-intl
import { useLocale } from 'next-intl';
import { useRouter, usePathname } from 'next-intl/client';

export function LanguageSwitcher() {
  const locale = useLocale();
  const router = useRouter();
  const pathname = usePathname();

  const switchLocale = (newLocale: string) => {
    router.replace(pathname, { locale: newLocale });
  };

  return (
    <div className="flex gap-1 text-sm" aria-label="Change language">
      <button
        onClick={() => switchLocale('en')}
        className={locale === 'en' ? 'font-bold' : 'opacity-50'}
      >
        EN
      </button>
      <span>|</span>
      <button
        onClick={() => switchLocale('es')}
        className={locale === 'es' ? 'font-bold' : 'opacity-50'}
      >
        ES
      </button>
    </div>
  );
}
```

> **Nota:** Este es un patrón orientativo. El dev debe adaptarlo al estilo exacto del NavBar actual (Tailwind classes, dark mode, etc.).

## Riesgos

| Riesgo | Probabilidad | Impacto | Mitigación |
|--------|-------------|---------|-----------|
| `useRouter` de next-intl no disponible si WasiNavBar es Server Component | Media | Alto | Convertir el switcher (o solo ese sub-componente) a Client Component con `'use client'` |
| El pathname al cambiar locale incluye el locale prefix duplicado | Media | Medio | Usar `usePathname` de `next-intl/client` que ya devuelve el path sin locale |
| En mobile el switcher no cabe en la barra — requiere ponerlo en el drawer | Baja | Bajo | Coordinar con diseño; si hay menú hamburguesa, añadirlo ahí |
| El middleware no persiste la preferencia de locale en cookie | Baja | Medio | Verificar config de `next-intl` middleware (`localeDetection`, cookie) |
| Dos botones EN/ES no son accesibles como toggle para screen readers | Baja | Bajo | Usar `role="group"` o un `<select>` accesible si se desea mayor robustez |
