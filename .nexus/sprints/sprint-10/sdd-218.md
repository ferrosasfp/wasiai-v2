# SDD-218 — On-chain como fuente de verdad para balances de keys

**Issue:** WAS-218
**Clasificación:** HU-MAJOR
**Dependencia:** WAS-216 (contrato V2 con `getKeyBalance`)
**Estado:** SPEC_APPROVED ✓ (2026-03-16)

## Context

`budget_usdc` y `spent_usdc` en la tabla `agent_keys` se han desincronizado múltiples veces del balance real on-chain. La UI muestra "available" negativo. La solución: `budget_usdc` pasa a ser un caché del valor on-chain, con `balance_synced_at` para tracking de frescura. `spent_usdc` se calcula para display, no se usa operacionalmente.

## Wave 2 — Backend: sync on read

### W2.1 Actualizar `AgentKey` interface + budget exhaustion check
Agregar en `agent-keys.service.ts`:
```typescript
balance_synced_at: string | null
```

**CRÍTICO:** Actualizar `validateAgentKey()` — actualmente usa `spent_usdc >= budget_usdc` para budget exhaustion. Con `budget_usdc` como on-chain truth, esta lógica se rompe (budget_usdc baja post-settlement, spent_usdc sigue subiendo → false exhaustion). Cambiar a:
```typescript
// ANTES (roto):
if (key.spent_usdc >= key.budget_usdc) return null
// DESPUÉS:
if (key.budget_usdc <= 0) return null // on-chain balance is 0 or negative = exhausted
```
Esto es seguro porque `budget_usdc` ahora refleja el balance real on-chain.

### W2.2 Actualizar GET `/api/agent-keys`
Después de obtener keys de DB, para cada key:
1. Intentar `getKeyBalanceOnChain(key.key_hash)`
2. Si éxito: actualizar `budget_usdc` y `balance_synced_at` en DB, retornar valor fresco con `stale: false`
3. Si falla (RPC error): retornar `budget_usdc` cacheado con `stale: true` y `synced_at: balance_synced_at`

**Optimización:**
- Hacer las llamadas on-chain en paralelo con `Promise.allSettled`. Si hay >10 keys, limitar concurrencia a 5.
- **Skip on-chain read si `balance_synced_at` es reciente (<30s)** — retornar cache con `stale: false` directamente. Evita N llamadas RPC en cada page load.

### W2.3 Actualizar sync-balance endpoint
Ya existe. Modificar para:
1. Agregar rate limit: 1 req/key/30s. Usar `checkRateLimit` de `src/lib/ratelimit.ts` (ya existe, usado en agent-keys/route.ts). Crear nuevo limiter con `Ratelimit.slidingWindow(1, '30 s')` y prefix `rl:sync`.
2. Retornar `{ budget_usdc, balance_synced_at, stale: false }`
3. Actualizar `balance_synced_at = NOW()` en la row

### W2.4 Post-settlement sync
En `settlement/route.ts`, después de tx confirmada:
```typescript
// Para cada key procesada en el batch:
const onChainBalance = await getKeyBalanceOnChain(keyHash)
await supabase.from('agent_keys').update({
  budget_usdc: onChainBalance,
  balance_synced_at: new Date().toISOString(),
}).eq('key_hash', keyHash)
```

## Critical Constraints

- **NO eliminar `spent_usdc`** de la tabla todavía — deprecar silenciosamente, no borrar columna
- **NO hacer on-chain reads en hot path de invoke** — solo en GET keys, sync, y post-tx
- Rate limit sync: 1 req/key/30s — no negociable (RPC abuse)
- `getKeyBalanceOnChain` ya devuelve USDC float (6 decimals converted) — no re-convertir
- Aplicar migración en dev Y prod simultáneamente (regla del proyecto)
- ESLint `--max-warnings 0`
- Si key no tiene `key_hash` válido (edge case legacy) → skip on-chain read, return stale
- **PROHIBIDO** dejar `validateAgentKey` usando `spent_usdc >= budget_usdc` — DEBE actualizarse a `budget_usdc <= 0`
- **PROHIBIDO** hacer on-chain read si `balance_synced_at` < 30s — usar cache
