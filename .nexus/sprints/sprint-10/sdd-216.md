## 1. Resumen

Se reescribe el contrato `WasiAIMarketplace` corrigiendo errores de arquitectura que bloquean el escalamiento: `settleKeyBatch` revierte si cualquier slug no está registrado (en vez de ser graceful), no existe `batchSelfRegister` (N txs para N agentes), y `ReputationRecord` no tiene métricas operacionales.

El nuevo contrato (V2) se deploya en Avalanche C-Chain mainnet reemplazando el actual. El costo de migración es bajo (~$0.83 USDC en contrato, 5 agentes propios). El estado del contrato actual NO se migra on-chain — los balances de keys y earnings se transfieren off-chain antes del cutover.

### Acceptance Criteria (EARS)

1. WHEN creator llama `batchSelfRegister([])`, THE contrato SHALL revertir con "WasiAI: empty batch"
2. WHEN creator llama `batchSelfRegister` con arrays de diferente largo, THE contrato SHALL revertir con "WasiAI: array length mismatch"
3. WHEN creator llama `batchSelfRegister` con slugs[].length > 50, THE contrato SHALL revertir con "WasiAI: batch too large"
4. WHEN creator llama `batchSelfRegister` con un slug ya registrado, THE contrato SHALL revertir con "WasiAI: slug taken: {slug}" (toda la tx)
5. WHEN `batchSelfRegister` es exitoso, THE contrato SHALL emitir `AgentRegistered` por cada slug
6. WHEN operator llama `settleKeyBatch` con mezcla de slugs registrados y no registrados, THE contrato SHALL procesar los registrados, skipear los no registrados emitiendo `SettlementSkipped`, y deducir del keyBalance SOLO el total de los registrados
7. WHEN operator llama `settleKeyBatch` con batch vacío, THE contrato SHALL revertir con "WasiAI: empty batch"
8. IF `settleKeyBatch` skipea un slug, THEN `keyBalances[keyId]` SHALL decrementarse únicamente por los amounts de slugs registrados
9. WHEN operator llama `submitReputationBatch`, THE contrato SHALL actualizar `ReputationRecord` con los 6 campos extendidos
10. WHEN el contrato está pausado, THE `batchSelfRegister`, `depositForKey`, `settleKeyBatch`, `recordInvocation` SHALL revertir con "Pausable: paused"
11. WHEN script de migración corre, THE 5 agentes WasiAI SHALL estar verificables via `getAgent(slug)` en el nuevo contrato

### 4.2 Cambios al contrato

#### Nueva función: batchSelfRegister

```
PRECONDICIONES:
- whenNotPaused
- slugs.length > 0 (revertir: "WasiAI: empty batch")
- slugs.length <= 50 (revertir: "WasiAI: batch too large")
- slugs.length == prices.length == erc8004Ids.length (revertir: "WasiAI: array length mismatch")
- Para cada slug: agents[slug].creator == address(0) (revertir: "WasiAI: slug taken: {slug}")

LÓGICA:
1. uint256 userCount = userRegistrationCount[msg.sender];
   uint256 freeRestantes = (userCount >= freeRegistrationsPerUser) ? 0 : freeRegistrationsPerUser - userCount;
   uint256 feeCount = (slugs.length > freeRestantes) ? slugs.length - freeRestantes : 0;
   uint256 totalFee = feeCount * registrationFee;
2. Si totalFee > 0: safeTransferFrom(msg.sender, address(this), totalFee)
3. userRegistrationCount[msg.sender] += slugs.length
4. Para cada i: agents[slugs[i]] = Agent(msg.sender, prices[i], erc8004Ids[i])
5. Emit AgentRegistered por cada i
```

**NOTA:** La forma ternaria es obligatoria para evitar underflow en Solidity 0.8.x checked arithmetic. `freeRegistrationsPerUser - userCount` revierte si `userCount > freeRegistrationsPerUser`.

#### Modificación: settleKeyBatch (lógica graceful)

```
CAMBIO CRÍTICO: Deducción post-loop (no pre-loop)

NUEVO FLUJO:
1. Validar: slugs.length == amounts.length, > 0, <= 500
2. Loop: para cada (slug, amount):
   - Si agents[slug].creator == address(0): emit SettlementSkipped(keyId, slug, amount); continue
   - Si amount == 0: revertir "WasiAI: zero amount"
   - platformShare = amount * platformFeeBps / 10000
   - creatorShare = amount - platformShare
   - earnings[agents[slug].creator] += creatorShare
   - totalEarnings += creatorShare
   - totalPlatformShare += platformShare
   - totalSettled += amount
   - totalVolume += amount; totalInvocations++
   - Emit KeyCallSettled
3b. _checkAndResetDailyWindow();
    require(dailySettledAmount + totalSettled <= dailySettlementCap, "WasiAI: daily cap exceeded");
    dailySettledAmount += totalSettled;
3. require(keyBalances[keyId] >= totalSettled, "WasiAI: insufficient key balance")
4. keyBalances[keyId] -= totalSettled
5. totalKeyBalances -= totalSettled
6. Si totalPlatformShare > 0: safeTransfer(treasury, totalPlatformShare)
```

**NOTA IMPORTANTE:** La verificación del balance se mueve al final del loop (sobre `totalSettled`). Esto permite que el loop calcule el total real antes de deducir. El daily cap check también se aplica sobre `totalSettled` post-loop — no se puede verificar antes porque el total real no se conoce hasta terminar el loop. La seguridad ante reentrancy está garantizada por `nonReentrant`: no hay external calls durante el loop.

### 4.4 Flujo principal: batchSelfRegister

1. Creator conecta wallet
2. Creator llama `batchSelfRegister(["slug1","slug2"], [price1,price2], [0,0])`
3. Contrato valida arrays, slugs disponibles, calcula fee
4. Si fee > 0: cobra USDC con safeTransferFrom
5. Registra todos, emite `AgentRegistered` × N
6. Creator queda como `agents[slug].creator` para todos

### 4.5 Flujo error: settleKeyBatch con slug no registrado

1. Operator llama `settleKeyBatch(keyId, ["slug-ok", "slug-missing"], [100, 200])`
2. Loop: "slug-ok" → acredita 90 a creator, 10 a platformShare, totalSettled += 100
3. Loop: "slug-missing" → emit `SettlementSkipped(keyId, "slug-missing", 200)`; totalSettled no cambia
4. `keyBalances[keyId] -= 100` (solo lo acreditado)
5. `safeTransfer(treasury, 10)`
