## Descripción

Permitir que el creador de un agente deshabilite el uso de Sandbox para su agente. Cuando `sandbox_enabled=false`, el endpoint de sandbox retorna HTTP 403 con código `sandbox_disabled`. El agente sigue visible en el listing.

---

## Wave 1 — DB Migration

**Archivo:** `supabase/migrations/051_sandbox_enabled.sql`

```sql
-- Migration 051: Sandbox opt-in/out
-- WAS-196 | Sprint 2
-- Agrega columna sandbox_enabled a tabla agents

ALTER TABLE agents
  ADD COLUMN IF NOT EXISTS sandbox_enabled BOOLEAN NOT NULL DEFAULT TRUE;

COMMENT ON COLUMN agents.sandbox_enabled IS 'Si false, el endpoint sandbox/invoke rechaza invocaciones con HTTP 403';

-- Índice parcial para discovery de agentes con sandbox habilitado (opcional, low-cardinality)
-- No se requiere índice: la columna se usa solo en lookup por slug (PK path)
```

**DB Security Checklist:**
- ✅ Sin SECURITY DEFINER (solo ALTER TABLE)
- ✅ Sin GRANTs adicionales necesarios (hereda permisos de tabla `agents`)
- ✅ RLS ya activo en `agents` desde migration base
- ✅ Sin SQL injection posible
- ✅ Sin RLS bypass

## Wave 2 — Route Fix (ajuste menor al body de error)

**Archivo:** `src/app/api/v1/sandbox/invoke/[slug]/route.ts`

El código actual retorna:
```ts
{ error: 'sandbox_disabled', message: 'This agent does not allow sandbox invocations.' }
```

AC-3 requiere:
```ts
{ error: 'Sandbox disabled by creator', code: 'sandbox_disabled' }
```

**Cambio mínimo (~3 líneas):**
```ts
// ANTES
return NextResponse.json(
  { error: 'sandbox_disabled', message: 'This agent does not allow sandbox invocations.' },
  { status: 403 }
)

// DESPUÉS
return NextResponse.json(
  { error: 'Sandbox disabled by creator', code: 'sandbox_disabled' },
  { status: 403 }
)
```
